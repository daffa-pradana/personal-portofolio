H5 – Jira Project Integration

Two-way OKR sync between Happy5 and Jira — and the three failures that shaped it.

Daffa Pradana Feb 18, 2026 · 8 min read
Ruby on Rails REST API Jira API Sidekiq
Product Page ↗
HERO IMAGE — SYNC FLOW DIAGRAM

Happy5 tracks OKRs. Engineering tracks work in Jira. For two years those were separate rituals: someone exported issues on Friday, pasted progress into a goal, and the number was stale by Monday. The brief was one sentence — make the goal update itself.

The naive version took an afternoon: poll the Jira API for issues matching a saved JQL query, sum story points, write progress. It also broke within a week. Jira rate-limits per app, not per tenant, so a handful of noisy workspaces starved everyone else’s sync.

Webhooks first, polling as a safety net

The fix was to invert it. Jira pushes an event, we enqueue one job per issue, and a nightly reconciliation job catches whatever the webhook dropped. Every job is keyed so a retry can’t double-count:

class SyncIssueJob
  include Sidekiq::Job
  sidekiq_options retry: 5, lock: :until_executed

  def perform(issue_id, event_ts)
    issue = JiraIssue.lock.find_by!(external_id: issue_id)
    return if issue.synced_at && issue.synced_at >= Time.at(event_ts)

    Goals::RecalculateProgress.call(issue.goal)
    issue.update!(synced_at: Time.at(event_ts))
  end
end

The synced_at guard is the whole trick. Events arrive out of order surprisingly often, and an idempotency key alone doesn’t protect you from an older event overwriting a newer number.

The backfill was the real deadline: 40,000 issues, one shot, during business hours.

We shipped the backfill as a throttled batch — 200 issues per tick, a Redash query watching lag, and a kill switch on a feature flag. It finished in four hours and nobody noticed, which is the best outcome a migration can get.

What it changed

Goal progress went from a Friday chore to a live number, and the support queue lost its most boring recurring ticket. The pattern — webhook, keyed job, nightly reconcile — became the template for the next two integrations we built.
